# flowersinagun.com: реконструкция от Wayback Machine

Този файл е пълният контекст на проекта. Ако продължаваш в нов чат с Claude, дай му този файл.

## Проектът накратко
- **Клиент:** Мартина Дечевска (САЩ), журналистка и брокер на недвижими имоти. Работя за нея и по AI агент за Follow Up Boss.
- **Задача:** да върна стария ѝ музикален блог flowersinagun.com (около 2013–2016) **с оригиналните URL адреси**, за да проработят старите линкове към него. Блогът е журналистическото ѝ портфолио. Иска и да пише там отново, така че ѝ трябва удобен редактор.
- **Източник:** само Wayback Machine. Bluehost потвърди писмено, че няма никакви бекъпи. Домейнът все още е неин.
- **Първоначална инвентаризация:** 178 статии, над 1 200 изображения и 8 автори.
- **Проект 2:** martinadechevska.com, прост и елегантен личен сайт. 400 €, ако е заедно с блога.

## Пари и договорка

## Защо скриптовете се пускат ръчно
web.archive.org е блокиран за средата на Claude. Скриптовете са готови и тествани с фалшиви данни, но **не са пускани срещу истинския Wayback.** Пускаш ги ти от своя терминал.

## Как се пуска (Windows, в тази папка)
```
pip install -r requirements.txt
python 01_inventory.py                  # около 1 мин. -> data/inventory.csv + summary
python 02_download.py --only html       # статиите, 178+ страници, около 10–30 мин.
python 03_parse.py                      # -> data/report.md, posts_index.csv, posts/*.json
python 02_download.py --only image      # 1 200+ снимки, около 1 час и повече (може да се спре и пусне пак)
python 02_download.py --extra data/missing_images.txt   # снимки, открити в статиите, но липсващи в CDX
python 03_parse.py                      # пак, за да се обновят липсващите снимки в доклада
```
- Всичко може да се прекъсне с Ctrl+C и да се пусне отново. Готовото се прескача.
- Ако Wayback връща много 429 или connection reset: `--delay 3`.
- Ако `inventory_summary.txt` покаже captures след изтичането на хостинга (около 2024), които са паркирани страници: `python 01_inventory.py --before 20230101`. Скриптът за сваляне така или иначе отхвърля паркирани страници и минава към по-стар snapshot.
- Ако искаш да видиш авторите и категориите от listing страниците: `python 02_download.py --only html --with-listings`.

## Файлове
| Файл | Какво прави |
|---|---|
| `common.py` | HTTP с retry/backoff, нормализиране на URL (без www/протокол/наклонена черта накрая), премахване на Wayback префикса от URL |
| `01_inventory.py` | CDX API → всички 200-OK captures → класификация: article / article_or_page / home / listing / image / theme_asset / noise / shortlink. Кандидат snapshot-и от най-новия към най-стария, по един на уникално съдържание |
| `02_download.py` | Сваля `/web/{ts}id_/{url}` (суров оригинал). Валидира HTML-а (не паркиран, не грешка, реален блог) и при проблем минава към по-стар snapshot. `data/manifest.csv` пази прогреса |
| `03_parse.py` | HTML → JSON: заглавие, дата, автор, категории, тагове, body_html, снимки, embeds. Мапва WordPress resized снимки (`-300x200.jpg`) към оригинала. Прави `report.md` и `posts_index.csv` (отваря се в Excel) |

## Какво предстои (в този ред)
1. **Пускане на стъпки 1–3 и проверка на report.md.** Колко статии са чисти, колко снимки липсват, кои embeds има (YouTube, SoundCloud…), дали платформата наистина е WordPress (виж `generator`). Пусни `posts_index.csv` и провери на око 5–10 статии спрямо Wayback в браузъра.
2. **Корекция на селекторите, ако е нужно.** Ако темата е нестандартна (празни body/author), погледни един HTML файл в `data/raw/html/` и добави правилния селектор в `BODY_SEL` / author в `03_parse.py`.
3. **Решение за цената и срока** според доклада. После отговор на Мартина.
4. **Решение за стека.** Критерии: 1:1 URL адреси (или 301), лесно писане за нея, реалистична цена на хостинга, поддръжка.
   - (a) **WordPress**: генерира се WXR (WordPress eXtended RSS) файл от `posts/*.json`, импортира се, permalink структурата се настройва като оригинала, снимките отиват в `wp-content/uploads` на същите пътища. Най-лесно е за нея и URL адресите се запазват естествено.
   - (b) **Next.js на Vercel с headless CMS** (моят стек). Импорт в CMS-а, routes със същите пътища. Повече контрол, но редакторът за нея е по-слаба страна и има повече поддръжка.
   - Засега моята препоръка е (a). Причините са, че тя ще пише, оригиналът почти сигурно е бил WordPress и шансът за точни URL адреси е най-голям. Потвърди след стъпка 1.
5. **Build:** импорт, снимките на оригиналните пътища, 301 за вариациите (с/без www, наклонена черта накрая, `?p=ID` shortlinks), проверка, че всеки URL от `inventory.csv` (article/page) връща 200.
6. **Предаване за преглед** (първи транш от 1 250 €), корекции, пускане (втори транш) и **жестът**.
7. После martinadechevska.com.
